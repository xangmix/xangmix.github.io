원래 지시문으로는 50회 중 35회 성공했습니다. 같은 뜻을 다른 표현으로 바꾸면 21회로 줄었고, 같은 장면의 다른 물체를 지시하면 원래 과제는 한 번도 성공하지 않았습니다. 영상을 보면 로봇은 새로 지시받은 물체(샐러드 드레싱)를 바구니에 넣었습니다.

수치는 모두 원래 과제(예: 알파벳 수프를 바구니에)의 성공 여부입니다. 조건마다 10개 과제 × 5회 = 50 에피소드입니다. 다음 날 같은 설정으로 다시 돌렸을 때 original과 paraphrase는 35/50, 21/50으로 똑같이 나왔습니다.

배경

왜 이 실험을 했나

스터디 주제는 VLA와 WAM의 비교입니다. 둘 다 로봇을 움직이는 AI 모델이지만, 데이터를 다루는 방식이 다릅니다.

VLA (Vision-Language-Action)WAM (World Action Model)
하는 일지금 화면과 지시문을 보고 다음 행동을 냄미래 영상과 행동을 함께 예측 (예: NVIDIA DreamZero)
시뮬레이터 안에서의 역할시뮬레이터 안에서 움직이는 정책(로봇의 두뇌)정책으로도 쓰고, (영상, 행동) 쌍을 만들어내는 신경망 시뮬레이터로도 씀
장점추론이 비교적 빠르고, 물리 시뮬레이터와 붙이면 성공 판정이 정확함3D 에셋 없이 다양한 장면을 만들 수 있고, 일반화가 더 좋다는 보고가 있음
한계학습 때 본 환경을 벗어나면 성능이 떨어지기 쉬움물리적으로 불가능한 장면(환각)이 섞일 수 있고, 추론이 느리고 GPU가 많이 필요함

로봇 학습에서 시뮬레이션이 필요한 이유

영상 데이터 자체는 많습니다. 부족한 것은 로봇의 행동(관절 값, 그리퍼 명령)이 짝지어진 영상입니다. 사람이 물건을 집는 영상은 인터넷에 넘치지만 행동 라벨이 없고, 로봇 데이터(Open X-Embodiment, DROID 등)는 다 합쳐도 언어·이미지 분야에 비하면 훨씬 작습니다.

물리 시뮬레이터는 이 문제를 풀어 줍니다. 행동을 넣으면 물리 법칙대로 물체가 움직이고, 정확한 행동 라벨과 성공 여부가 자동으로 나옵니다. 렌더링만 해서는 "이 행동을 하면 물체가 이렇게 움직인다"는 인과가 영상에 담기지 않기 때문에, 행동을 배우는 모델에는 물리 엔진이 필요합니다. 그래서 VLA 연구는 LIBERO 같은 시뮬레이션 벤치마크에서 성능을 비교합니다.

문제의식: 점수가 높으면 지시를 이해하는 걸까?

최신 VLA는 LIBERO에서 거의 만점을 받습니다. LeRobot 재현 결과로 π0.5는 평균 97.5%, LIBERO-Object에서는 99%입니다. 그런데 LIBERO-PRO와 LIBERO-Plus 같은 후속 연구는 물체 위치, 카메라 각도, 지시문을 조금만 바꿔도 성능이 크게 떨어지고, 모델이 언어 지시를 거의 무시하는 경향이 있다고 보고합니다. 그렇다면 "높은 점수 = 지시를 이해함"이라고 말할 수 없습니다.

그래서 이 실험은 다른 조건은 모두 고정하고 지시문 하나만 바꿔서, VLA가 문장을 실제로 읽고 행동하는지 직접 확인합니다.

실습 범위를 이렇게 정한 이유

  • WAM은 실습 대신 이론으로: 현재 WAM은 대형 영상 생성 모델 기반이라 고성능 GPU 여러 장이 필요하고 추론도 느립니다. 하루짜리 실습, 무료 Colab에서는 현실적이지 않습니다.
  • VLA는 작은 모델로: 무료 Colab의 T4 GPU에서 돌아가는 SmolVLA를 골랐습니다(아래 모델 섹션).
  • Mac 대신 Colab: LIBERO는 Linux 전용이라 Mac에서는 돌릴 수 없습니다. Colab은 Linux와 GPU를 무료로 제공합니다.
사용한 모델

SmolVLA: 이미지와 문장을 받아 로봇 행동을 내는 모델

VLA(Vision-Language-Action)는 이미지와 문장을 이해하는 비전-언어 모델(VLM)에 로봇 행동을 출력하는 부분을 붙인 모델입니다. 카메라 화면과 "무엇을 하라"는 문장을 함께 넣으면, 로봇팔이 다음에 어떻게 움직일지를 숫자로 내놓습니다.

이번에 쓴 SmolVLA는 Hugging Face가 공개한 약 4.5억 파라미터짜리 작은 VLA입니다. 아래 구조와 숫자는 실행 로그에 찍힌 모델 설정에서 가져왔습니다.

SmolVLA를 고른 이유

이유설명
작다약 4.5억 파라미터라 무료 Colab T4 GPU로 돌아갑니다. π0처럼 수십억 파라미터인 모델은 더 큰 GPU가 필요합니다.
LIBERO용 체크포인트가 공개돼 있다직접 학습하지 않고 바로 평가할 수 있습니다.
LeRobot에 통합돼 있다설치와 평가가 명령어 몇 줄로 끝납니다.
언어 지시를 받는다지시문을 바꾸는 실험이 가능합니다.

단점은 최고 성능 모델이 아니라는 점입니다. 논문 기준 LIBERO 평균 성공률은 SmolVLA가 약 87%, π0.5가 약 97%입니다. 구조는 π0(VLM + action expert + flow matching)를 작게 줄인 형태입니다.

학습

우리는 학습하지 않았다: 공개 체크포인트를 평가만 했다

이 실험에서 모델 가중치는 한 번도 바뀌지 않았습니다. 이미 LIBERO 데이터로 학습된 공개 체크포인트를 내려받아, 시뮬레이터에서 실행(추론)만 했습니다. 바꾼 것은 모델에 들어가는 문장 하나뿐입니다.

체크포인트는 어떻게 학습됐나

모방 학습(행동 복제)입니다. 사람이 로봇을 조종해 과제를 해낸 시연 데이터에서 (카메라 화면, 로봇 상태, 지시문) → (사람이 실제로 한 행동) 쌍을 뽑아, 모델이 같은 상황에서 같은 행동을 내도록 학습합니다. 행동 전문가는 flow matching 방식으로, 잡음 섞인 행동에서 정답 행동 쪽으로 가는 방향을 맞히도록 학습됩니다.

체크포인트 설정 파일에 기록된 학습 관련 값은 다음과 같습니다.

freeze_vision_encoder
True: 이미지 인코더는 학습하지 않음
train_expert_only
True: VLM은 고정하고 행동 전문가(와 상태 입력층)만 학습
optimizer
학습률 1e-4, betas (0.9, 0.95), gradient clip 10
scheduler
warmup 1,000 스텝, 감쇠 30,000 스텝, 최종 학습률 2.5e-6

토론 포인트: 문장을 이해하는 VLM 부분은 고정돼 있고, 학습된 건 "VLM이 만든 표현을 행동으로 바꾸는 부분"뿐입니다. 그렇다면 로봇이 문장에 반응한다는 건, 행동 전문가가 VLM 표현 속의 물체 이름을 행동 선택에 쓰도록 학습됐다는 뜻입니다.

실험 설계

장면은 그대로, 문장만 바꾼 4가지 조건

LIBERO-Object는 식료품 물체 여러 개가 놓인 테이블에서 "X를 집어 바구니에 넣어라"를 수행하는 10개 과제 묶음입니다. 과제마다 고정된 시작 장면이 있고, 성공 여부는 시뮬레이터가 물체가 바구니 안에 들어갔는지로 자동 판정합니다.

조건정책에 들어간 문장 (0번 과제)언어를 이해한다면
originalpick up the alphabet soup and place it in the basket높은 성공률 (기준선)
paraphrasegrab the alphabet soup and put it into the basket기준선과 비슷
wrong_objectpick up the salad dressing and place it in the basket원래 과제 성공률 하락
nonsensewhat is the weather like today원래 과제 성공률 하락

wrong_object의 물체는 지어낸 이름이 아니라, 과제 정의 파일(BDDL)에서 같은 장면에 실제로 놓여 있는 다른 물체를 골랐습니다. 반대로 wrong_object나 nonsense에서도 원래 과제를 잘 해낸다면, 정책이 문장 대신 화면 배치만 보고 과제를 추측한다는 증거가 됩니다.

문장을 바꾼 방법

LeRobot 평가 코드는 매 스텝 환경의 task_description을 읽어 정책에 넘깁니다. 그래서 환경이 만들어지는 순간 이 값만 바꿔치기했습니다. 장면, 초기 상태, 성공 판정은 손대지 않았습니다.

# run_eval.py (일부)
def _patched_init(self, *args, **kwargs):
    _original_init(self, *args, **kwargs)
    used = make_instruction(self.task_description, self._task_bddl_file, MODE)
    self.task_description = used   # 정책이 읽는 문장만 교체

libero_env.LiberoEnv.__init__ = _patched_init
lerobot_eval.main()

시연 영상

같은 장면, 다른 문장

2번 과제 (salad dressing): 표현만 바꿨을 때

무엇을 알 수 있나

  • 정책은 문장 속 물체 이름을 근거로 행동을 고른다

    LIBERO-Object는 과제마다 물체 배치가 달라서, 화면만 보고도 무슨 과제인지 짐작할 수 있습니다. 그래서 "모델이 문장을 무시하고 배치만 볼 것"이라는 가설도 가능했습니다. 하지만 물체 이름을 바꾸자 원래 과제 성공은 0회였고, 영상에서는 새로 지시한 물체를 옮겼습니다. 이 가설과 반대되는 결과입니다.

  • 하지만 같은 뜻을 다른 말로 하면 흔들린다

    pick up → grab, place it in → put it into로 바꾸자 성공률이 70%에서 42%로 떨어졌습니다. 핵심 단어(물체 이름)에는 민감하게 반응하면서도, 학습 때 본 문장 형태에 상당히 의존한다는 뜻입니다. 하락은 고르지 않아서, salad dressing(5→0)과 butter(5→2)처럼 크게 무너지는 물체가 있는 반면 chocolate pudding은 그대로였습니다.

  • 선행 연구와 비교하면

    LIBERO-Plus는 여러 VLA가 언어 지시를 거의 무시하는 경향이 있다고 보고했습니다. 이번 실험에서 SmolVLA는 적어도 물체 이름에는 반응했으니, 그 경향과는 다른 결과입니다. 반면 같은 뜻의 다른 표현에 약한 점은, LIBERO의 높은 점수가 상당 부분 학습 데이터 암기라는 LIBERO-PRO의 지적과 맞닿아 있습니다. 다만 모델, 과제 묶음, 바꾼 요인이 서로 달라서 직접 비교할 수는 없습니다.

  • 엉뚱한 문장에 대한 반응은 아직 모른다

    nonsense 조건은 본 실험 도중 런타임이 끊겨 결과가 없습니다. 재실행으로 확인할 예정입니다.

여기까지 온 순서

  3. 동작 확인

    0번 과제를 1회 돌려 설치를 확인했습니다. 실험 프로그램이 Colab의 그래프 설정(MPLBACKEND)을 물려받아 멈추는 문제를 고쳤고, 설정 셀을 건너뛰어 난 NameError는 셀을 순서대로 실행해 해결했습니다.

  4. 본 실험 (약 4시간)

    original 63분 → paraphrase 80분 → wrong_object 98분 순서로 3개 조건을 마쳤습니다.

  5. 런타임 끊김과 결과 소실

    nonsense 조건 도중 Colab 런타임 연결이 끊겼고, 런타임을 삭제하면서 /content에 있던 결과 파일과 영상이 모두 사라졌습니다. 화면에 출력된 3개 조건의 성공률만 남았습니다.

  6. 저장 위치 변경 후 시연 영상 확보

    결과가 Google Drive에 저장되도록 바꾸고, 조건마다 0번 과제를 1회씩 다시 돌려 위의 영상 4개를 얻었습니다.

  7. 재실행 (10월 20일)

    Drive에 저장하면서 4개 조건을 다시 돌렸습니다. original 35/50, paraphrase 21/50으로 1차와 똑같이 나왔고, 이번에는 과제별 결과와 영상 100개가 남았습니다. wrong_object를 29회째 돌리던 중 Colab GPU 사용량 한도에 걸려 멈췄습니다.

  8. 다음: 남은 조건

    GPU 한도가 풀리면 wrong_object와 nonsense를 마저 돌립니다. 끝난 조건은 건너뛰므로 약 3.3시간이 걸립니다.

공부하면서 나온 질문들

실험을 준비하면서 헷갈렸던 용어와 배경 지식을 질문과 답으로 정리했습니다.

모델

QAction expert가 뭔가요?

VLM 옆에 붙은, 로봇 동작만 전문으로 만드는 작은 신경망입니다.

  • VLM은 눈과 귀 역할입니다. 영상과 지시문을 이해해서 "무엇을 할지"를 담당합니다.
  • Action expert는 손 역할입니다. VLM이 이해한 내용을 받아 flow matching으로 움직임 숫자를 만들어 "어떻게 움직일지"를 담당합니다.

따로 두는 이유는, 언어 모델은 단어를 하나씩 출력하는 데 특화돼 있는데 로봇에는 빠르고 연속적인 숫자가 필요하기 때문입니다. SmolVLA의 action expert는 VLM의 절반 폭(expert_width_multiplier: 0.5)으로 작게 만들어졌습니다.

QFlow matching은 무슨 뜻인가요?

노이즈에서 출발해 조금씩 정답 행동으로 다듬어 가는 생성 방법입니다.

  1. 무작위 값(노이즈)으로 된 엉터리 행동에서 시작합니다.
  2. 모델이 "이 방향으로 조금 옮겨라"를 알려 줍니다.
  3. 이것을 여러 번 반복합니다. SmolVLA는 10번입니다(num_steps: 10).
  4. 마지막에 부드럽고 정확한 행동 50스텝이 나옵니다.

대충 그린 스케치를 여러 번 고쳐 그려 완성하는 것과 비슷합니다. 이미지 생성 AI(diffusion)와 같은 계열입니다. 같은 일을 하는 방법이 여러 가지일 때(장애물을 왼쪽으로 돌아가도, 오른쪽으로 돌아가도 됨), 정답을 평균 내서 어중간한 행동(가운데로 돌진)이 나오는 문제를 피할 수 있다는 장점이 있습니다.

Q체크포인트(checkpoint)는 무엇인가요?

학습이 끝난 모델의 상태를 저장한 파일입니다. 게임의 세이브 파일과 같습니다. HuggingFaceVLA/smolvla_libero는 SmolVLA를 LIBERO 데이터로 추가 학습한 뒤 저장한 것이고, 안에는 학습된 숫자들(가중치, model.safetensors)과 설정 파일(config.json)이 들어 있습니다. 우리는 이 체크포인트를 불러와서 평가만 했습니다.

Qπ0, π0.5는 무엇인가요? 평가지표인가요?

평가지표가 아니라 모델 이름입니다. 평가지표는 성공률이고, π0와 π0.5는 "이 모델보다 잘하나?"를 비교하는 기준 모델(baseline)로 많이 쓰입니다. 로봇 AI 스타트업 Physical Intelligence가 만들었고, π는 회사 이름에서 따왔습니다. 둘 다 openpi로 공개돼 있습니다.

벤치마크 (LIBERO)

QLIBERO-90, LIBERO-100 같은 건 무엇이 다른가요?

LIBERO에는 과제 묶음(suite) 5개, 과제 총 130개가 있고, 묶음마다 한 가지 능력만 따로 시험하도록 설계됐습니다.

묶음과제 수무엇이 바뀌나시험하는 능력
LIBERO-Spatial10같은 물체, 위치만 다름 ("접시 옆의 그릇")공간 관계 이해
LIBERO-Object (이번 실험)10어떤 물체를 집을지가 다름물체 구별
LIBERO-Goal10같은 장면, 목표가 다름 (서랍 열기, 그릇 올리기 등)목표 이해
LIBERO-100100위 요소가 모두 섞인 다양한 과제종합
  └ LIBERO-9090짧은 과제원래 용도는 사전학습용
  └ LIBERO-10 (Long)10여러 단계를 이어 하는 긴 과제긴 작업 수행

LIBERO-100 = LIBERO-90 + LIBERO-10입니다. VLA 논문들은 보통 Spatial, Object, Goal, Long 네 묶음의 성공률을 보고하고, 과제마다 사람이 시연한 데이터 50개로 학습합니다.

이번 실험과 관련해 중요한 점은, LIBERO-Object는 과제마다 장면에 놓인 물체 조합이 다르다는 것입니다. 0번 과제 장면에는 알파벳 수프, 샐러드 드레싱 등이 있고, 7번 과제에는 우유, 오렌지 주스 등이 있습니다. 그래서 모델이 지시문을 읽지 않아도 화면만 보고 몇 번 과제인지 짐작할 수 있습니다.

Q여기서 Benchmarking은 어떤 의미인가요?

모두가 같은 조건에서 시험을 봐서 점수를 비교할 수 있게 만드는 것입니다. 수능처럼 같은 문제, 같은 채점 기준을 씁니다. LIBERO는 과제, 시연 데이터(과제당 50개), 초기 장면, 성공 판정 규칙, 시도 횟수를 모두 고정합니다.

발표 포인트는 의도가 바뀌었다는 점입니다.

  1. 원래 의도: 논문 제목이 Benchmarking Knowledge Transfer for Lifelong Robot Learning입니다. 로봇이 과제를 하나씩 차례로 배울 때, 앞서 배운 지식이 새 과제에 도움이 되는지(전이), 이전 과제를 잊는지(망각)를 측정하려 했습니다.
  2. 지금 쓰이는 방식: VLA 연구자들이 여러 과제를 한꺼번에 학습한 뒤 성공률을 재는 표준 시험지로 쓰고 있습니다.
  3. 그래서 생긴 문제: 학습과 시험이 거의 같은 장면이라 암기만 해도 고득점이 가능합니다. LIBERO-PRO와 LIBERO-Plus가 지적한 부분입니다.

이번 실험은 다른 조건을 다 고정하고 지시문 하나만 바꾼 통제 실험입니다. "LIBERO 점수가 언어 이해를 측정하는가?"를 확인하는 작은 강건성 벤치마크를 직접 만들어 본 셈입니다.

QLIBERO 점수는 어떻게 매기고, 무엇을 나타내나요? 우리 실험에서는 어디에 쓰이나요?

매기는 방법

  1. 과제마다 고정된 초기 장면에서 에피소드를 여러 번 시작합니다.
  2. 과제 정의 파일(BDDL)에 적힌 목표 조건을 매 스텝 검사합니다. 예: "알파벳 수프가 바구니 안에 있다"
  3. 최대 스텝 안에 조건이 만족되면 성공, 아니면 실패입니다.
  4. 성공 횟수 ÷ 전체 에피소드 × 100이 점수이고, 묶음별 점수와 평균을 보고합니다.

나타내는 것: 학습 때 본 과제와 환경을 얼마나 잘 재현하는지입니다. 새로운 상황에 대한 일반화나 언어 이해는 직접 측정하지 않습니다.

우리 실험에서 쓰인 곳

  • 기준선 확인: original 조건 점수가 공개 수치와 비슷하면 실험 환경이 제대로 구축됐다는 증거입니다. 이번에는 70%로, 논문의 SmolVLA LIBERO 평균(약 87%, 네 묶음 평균)보다 낮았습니다. n_action_steps를 10으로 바꾼 영향일 수 있지만 따로 확인하지는 않았습니다.
  • 측정 도구: 네 조건 모두 LIBERO의 성공 판정기로 "원래 과제를 해냈는가"를 잽니다. 판정 기준이 같아야 공정하게 비교할 수 있습니다.
  • 결론의 근거: 지시문을 엉뚱하게 바꿔도 점수가 그대로라면 "LIBERO 점수는 언어 이해를 측정하지 못한다"는 근거가 되고, 점수가 떨어지면 모델이 언어를 쓴다는 근거가 됩니다. 이번 wrong_object 결과는 후자였습니다.

Qπ0.5가 LIBERO에서 95% 넘게 받는다는 게 이해가 안 돼요. 일반화를 잘한다는 뜻인가요?

서로 다른 맥락의 숫자 두 개가 섞여 있어서 헷갈리기 쉽습니다.

  • 약 97%: π0.5를 LIBERO 학습 데이터로 추가 학습한 뒤 LIBERO 과제로 시험한 성공률입니다. LeRobot 재현 결과로 평균 97.5%, LIBERO-Object만 보면 99%입니다.
  • "95%에서 30% 미만으로": LIBERO-Plus의 결과입니다. 원래 LIBERO에서 95% 정도 나오던 모델들이 카메라 각도나 로봇 초기 자세를 조금만 바꿔도 30% 아래로 떨어졌다는 뜻입니다.

즉 97%는 연습 문제와 거의 같은 시험에서 받은 점수라서 일반화 능력을 보여주는 숫자가 아닙니다. 그래서 "LIBERO 점수는 이미 포화됐다(다들 만점 근처)"는 비판이 나옵니다.

평가 용어

Q스텝과 에피소드는 어떻게 다른가요?

단위뜻LIBERO에서
스텝 (step)로봇이 한 번 보고 한 번 움직이는 최소 단위1초에 20스텝 (1스텝 = 0.05초)
에피소드 (episode)장면을 처음 상태로 되돌린 뒤, 성공하거나 시간이 다 될 때까지 한 번 시도한 것LIBERO-Object는 최대 280스텝 (시뮬레이션 시간 약 14초)

컵 옮기기를 한 번 시도한 것이 1 에피소드이고, 그 안에 동작이 수백 스텝 들어 있습니다. 우리 설정에서는 모델이 50스텝 분량을 예측하고 그중 10스텝을 실행한 뒤 다시 예측합니다. 시뮬레이션 안에서는 14초짜리 에피소드가 T4 GPU에서는 실제로 1~2분 걸렸습니다. 매 스텝 렌더링과 모델 추론 때문입니다.

Q성능은 어떤 지표로 나타내나요?

성공률(success rate), 즉 전체 에피소드 중 성공한 에피소드의 비율입니다. "70%"는 50번 시도해서 35번 성공했다는 뜻입니다. 성공 여부는 사람이 아니라 시뮬레이터가 자동으로 판정합니다. 이번 실험에서는 시도 횟수가 많지 않아서, 성공률과 함께 95% 신뢰구간도 표시했습니다.

Q200번 실험했으니 LIBERO-200인가요?

아닙니다. 묶음 이름의 숫자는 과제 종류의 개수이고, 200은 시도 횟수입니다.

LIBERO-Object 과제 10개 × 과제당 5번 × 조건 4개 = 200 에피소드

같은 과제 10개를 반복해서 시도했으니 우리가 쓴 묶음은 LIBERO-Object이고, 조건 하나당 50 에피소드입니다.

Colab 실행 환경

QNameError: name 'run' is not defined가 왜 났나요?

Colab 노트북의 셀들은 각각 따로 실행되는 파일이 아니라, 하나의 파이썬 프로세스(커널)의 메모리를 같이 씁니다. run 함수는 3번 설정 셀에서 def run(...)으로 정의되는데, 이 셀을 실행해야 비로소 커널 메모리에 run이라는 이름이 생깁니다.

설정 셀을 건너뛰고 4번 셀을 실행했거나, 설정 셀을 실행한 뒤 런타임이 재시작되면 메모리가 비워져 같은 오류가 납니다. 해결은 설정 셀을 먼저 실행하는 것입니다. 메뉴의 런타임 → 이전 셀 실행(Ctrl+F8)을 쓰면 현재 셀 위를 한 번에 실행할 수 있습니다.

Q동작 확인(smoke = run(...))이 robosuite 경고만 잔뜩 출력하고 멈췄어요.

맨 위의 No private macro file found 경고는 무시해도 되는 메시지입니다. 실제 원인은 Colab의 그래프 설정이 실험 프로그램에 그대로 넘어간 것이었습니다.

Colab은 노트북 안에 그래프를 띄우려고 MPLBACKEND=module://matplotlib_inline.backend_inline이라는 환경변수를 설정해 둡니다. run()이 실행하는 실험 프로그램이 이 값을 물려받았는데, 따로 만든 가상환경에는 그 모듈이 없어서 matplotlib을 불러오는 단계에서 멈췄습니다.

해결은 실험 프로그램에만 화면 없이 그리는 방식을 지정하는 것입니다. run() 안의 환경변수에 MPLBACKEND="Agg"를 추가했고, 노트북에서 그래프를 그리는 부분은 영향을 받지 않습니다. 설치는 다시 할 필요가 없었습니다.

Q"연결 중", "재개 중"이 계속 뜰 때 브라우저를 새로고침해도 되나요?

됩니다. 실제 계산은 Google 서버의 런타임에서 돌고, 브라우저는 화면만 보여줍니다. 새로고침하면 같은 런타임에 다시 연결되고, 커널의 변수와 /content의 파일도 그대로 남습니다. 저장되지 않은 노트북 화면 출력만 사라질 수 있습니다.

반대로 런타임 → 런타임 연결 해제 및 삭제는 서버 자체를 지웁니다. 이번에 결과를 잃은 이유가 이것입니다. 다만 "재개 중"이 몇 분 넘게 계속된다면 런타임이 이미 회수된 경우가 많아서, 그때는 삭제하고 새로 연결하는 수밖에 없습니다.

Q결과 파일은 왜 사라졌고, 어떻게 막았나요?

/content는 런타임 서버의 임시 디스크입니다. 런타임이 사라지면 결과 파일과 설치한 가상환경(/content/venv)이 함께 지워집니다. 그래서 다시 연결하면 1번 설치 셀부터 다시 실행해야 합니다.

해결책은 결과를 Google Drive에 저장하는 것입니다. 설정 셀에서 drive.mount("/content/drive")로 Drive를 연결하고, 저장 위치 변수 RESULTS를 Drive 경로로 바꿨습니다. RESULTS는 파일이 아니라 "어디에 저장할지"를 담은 변수일 뿐입니다.

run()은 결과 파일(eval_info.json)이 이미 있는 조건은 건너뛰도록 만들었습니다. 그래서 끊긴 뒤 다시 실행하면 끝난 조건은 넘어가고, 진행 중이던 조건만 처음부터 다시 돕니다. 실제로 2차 실행이 GPU 한도로 멈췄을 때 original과 paraphrase의 데이터는 Drive에 남아 있었습니다.

Q"GPU 사용량 한도"는 무엇인가요?

무료 Colab은 GPU를 쓸 수 있는 시간에 제한이 있고, 기준은 공개되지 않습니다. 1차 실행 약 4시간 뒤, 다음 날 2차 실행은 약 3.5시간 뒤에 한도에 걸렸습니다. 보통 몇 시간에서 하루 정도 지나면 다시 쓸 수 있습니다. 급하면 Colab 컴퓨팅 단위를 구매하거나, 무료 GPU 시간을 주는 Kaggle Notebook으로 옮기는 방법이 있습니다.

실험 시간

Q조건 하나에 1시간이 넘게 걸리는 게 정상인가요?

정상입니다. 조건마다 50 에피소드, 4개 조건이면 200 에피소드입니다. 에피소드 하나는 시뮬레이터에서 로봇을 초당 20스텝씩 움직이면서, 매 스텝 카메라 2대의 화면(360×360)을 렌더링하고 0.5초마다 모델을 추론합니다.

성공하면 그 자리에서 에피소드가 끝나지만, 실패하면 제한 시간까지 끝까지 돕니다. 그래서 실패가 많은 조건일수록 오래 걸렸습니다.

조건성공률에피소드당 (1차 / 2차)조건 전체 (1차 / 2차)
original70%75초 / 80초63.2분 / 67.7분
paraphrase42%95초 / 99초80.1분 / 83.0분
wrong_object0%117초 / —97.9분 / 중단

설정이 잘못돼서 느린 건 아닌지도 확인했습니다. 실행 로그에서 모델이 GPU(device: cuda)에서 돌았고 n_action_steps: 10이 적용된 것을 확인했습니다. 체크포인트 기본값(1, 매 스텝 추론)이었다면 추론 횟수가 10배라 훨씬 느렸을 겁니다.

Q셀이 1시간 넘게 아무것도 출력하지 않는데, 멈춘 건가요?

아닙니다. run()은 LeRobot 평가 프로그램을 별도 프로세스로 실행하고, 그 출력을 모아 뒀다가(capture_output=True) 조건 하나가 끝나야 한 줄을 출력합니다. 그래서 첫 조건이 끝날 때까지 조용한 게 정상입니다.

진행 상황은 왼쪽 파일 패널에서 <조건>/videos/ 폴더의 .mp4 개수로 확인할 수 있습니다. 에피소드 하나가 끝날 때마다 영상이 하나씩 늘어납니다.

Q4번 동작 확인 셀의 예상 시간보다 왜 훨씬 오래 걸렸나요?

예상 시간은 original 조건으로 0번 과제를 1번 돌린 시간에 200을 곱해 계산합니다. 그런데 wrong_object, nonsense처럼 실패가 많은 조건은 에피소드마다 제한 시간까지 도니까, 실제 전체 시간은 예상보다 1.5~2배 길어집니다.

결과 해석

Qwrong_object가 0%면 로봇이 아무것도 못 한 건가요?

아닙니다. 이 실험은 모든 조건을 원래 과제 기준으로 채점합니다. 0번 과제에 "샐러드 드레싱을 넣어라"라고 지시하면, 로봇이 지시대로 샐러드 드레싱을 바구니에 넣어도 "알파벳 수프가 바구니에 없으므로 실패"로 기록됩니다.

실제 영상에서 로봇은 샐러드 드레싱을 집어 바구니에 넣었습니다. 그래서 0%는 "원래 과제를 하지 않았다", 즉 바뀐 문장을 따랐다는 뜻으로 읽어야 합니다. 로봇이 한 에피소드에 물체를 두 개씩 옮기지는 않으니, 문장을 따르는 한 원래 과제가 우연히 성공할 일도 거의 없습니다.

모델이 문장을 무시하고 화면 배치만 봤다면 original과 비슷한 70% 근처가 나왔어야 합니다. 0/50(95% 신뢰구간 0~7.1%)은 그와 확실히 다릅니다.

로봇이 바뀐 지시를 수행할 수 있었던 데도 이유가 있습니다. 바꿔 넣은 물체는 같은 장면에 실제로 놓인 물체이고, 모두 다른 과제의 목표 물체입니다. 0번 과제에서 지시한 salad dressing은 2번 과제의 목표 물체로, 모델이 5/5로 성공한 과제입니다. 모델에게 익숙한 명령을 다른 배치의 장면에서 받은 셈입니다.

다만 50회 중 몇 번이나 바뀐 물체를 제대로 옮겼는지는 자동으로 측정하지 않았습니다. 재실행에서 남은 wrong_object 영상 29개를 직접 세거나, 바뀐 물체 기준의 성공 판정 코드를 추가하면 숫자로 보일 수 있습니다.

Q시연 영상에서 original도 실패했는데, 실험이 잘못된 건가요?

아닙니다. 시연 영상은 0번 과제의 1회차 시작 장면인데, 재실행 데이터를 보면 이 장면은 본 실험에서도 실패했습니다(위 과제별 표의 0번 과제 ○●●●○에서 첫 칸). 성공률 70%인 모델이라 실패하는 장면이 있고, 같은 seed와 같은 시작 장면이면 결과도 같습니다. 그래서 성공 장면을 보여 주려고 5회 모두 성공한 2번 과제 영상을 따로 넣었습니다.

Q다시 돌렸더니 숫자가 완전히 같았던 이유는?

seed(1000)와 LIBERO의 고정 초기 상태를 그대로 썼기 때문에, 두 번 모두 같은 시작 장면에서 같은 난수로 실행됐습니다. 35/50, 21/50이 그대로 나온 건 실행 과정이 사실상 결정적이라는 뜻이고, 실험 파이프라인을 믿을 수 있다는 근거가 됩니다.

하지만 독립된 반복 실험은 아닙니다. 다른 seed(다른 시작 장면)에서도 비슷한 성공률이 나오는지는 아직 확인하지 않았습니다.

Q숫자는 이미 있었는데 왜 다시 돌렸나요?

1차 결과는 화면에 출력된 숫자 3개만 남아서, 과제별 분석도 영상도 없었습니다. 재실행으로 과제별 결과가 생기면서 "salad dressing은 표현을 바꾸면 5/5에서 0/5로 무너진다" 같은 새로운 관찰을 얻었고, 원래 과제를 성공하는 영상도 확보했습니다. 남은 wrong_object와 nonsense는 GPU 한도가 풀리면 마저 돌립니다.

한계

이 결과를 읽을 때 주의할 점

  • 조건당 50 에피소드라 신뢰구간이 넓습니다(original 기준 ±12%p 안팎).
  • 재실행 결과가 같았던 건 seed와 시작 장면이 같아서입니다. 실험 과정이 재현된다는 뜻이지, 다른 seed에서도 같은 성공률이 나온다는 뜻은 아닙니다.
  • n_action_steps를 10으로 바꿔서 공개된 성능과 절대 수치가 다를 수 있습니다.
  • wrong_object에서 로봇이 지시한 물체를 옮겼는지는 자동으로 판정하지 않았습니다. 샐러드 드레싱을 옮긴 장면은 영상 1개에서 본 사례입니다.
  • paraphrase는 하나의 고정된 문장 틀(grab … put it into …)만 시험했습니다.
  • 모델 1개, 과제 묶음 1개(LIBERO-Object)에 대한 결과입니다.
